## 2024-05-23 - MoE Routing Optimization
**Learning:** Significant speedups can be achieved in MoE routing by replacing `argsort` with `jax.lax.top_k` (~18x) and `one_hot().sum()` with `jnp.bincount` (~15x). However, these gains may be masked by inefficient expert execution loops in naive implementations.
**Action:** Always verify micro-benchmarks for component-level optimizations when end-to-end impact is limited by other bottlenecks. Ensure `uv.lock` is not accidentally modified during dependency resolution.

## 2024-04-08 - JAX Memory OOM from Stacking Expert Outputs
**Learning:** In JAX/Flax Mixture of Experts (`MoELayer`), eagerly computing and stacking all expert outputs into a massive intermediate tensor (`jnp.stack([expert(x) for expert in experts], axis=0)`) before gathering the top-k results causes a massive memory footprint, leading to silent XLA Out-of-Memory (OOM) errors on large compilations. The `jnp.stack` creates a tensor of size `(num_experts, batch_size, seq_len, d_model)` which scales disastrously with the number of experts.
**Action:** When implementing expert routing loops in JAX, avoid `jnp.stack`. Instead, iterate over experts and accumulate the results by tracking `(top_k_indices == expert_index)` masks. While this still executes each expert, it drastically improves XLA compilation times and significantly reduces the intermediate memory overhead (observed memory diff drops from 504MB to 254MB on test benchmarks).
